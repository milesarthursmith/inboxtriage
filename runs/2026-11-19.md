## Tooling: `search_threads` undercounts, silently

`THREAD_VIEW_SUMMARY` returned 35 threads. `THREAD_VIEW_IDS_ONLY` returned 40.
Five thread IDs appear **only** in `IDS_ONLY`; every other view omits them with
no marker, and `get_thread` returns `{"messages": []}` for each in every format
(PLAIN_TEXT, MINIMAL, METADATA_ONLY). This matches the documented behaviour that
spam / suspicious / encrypted / confidential mail is filtered out before the
search runs.

**Consequence: a run that reads only the SUMMARY or MINIMAL listing silently
skips threads.** Count with `IDS_ONLY` and reconcile against the readable
listing, every run. Last run's note that `resultCountEstimate` is unreliable
still holds — it read 40 and 41 against true counts of 40 and 20.

The five unreadable threads (all ~11 Nov) were left in the inbox untouched:
